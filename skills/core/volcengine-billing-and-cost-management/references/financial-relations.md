# 财务托管与付费归属

用户问“谁替我付账”“我是不是托管账号”“余额和信用额度都是零，为什么还能使用”，
或主账号问“替哪些成员付了多少”时，按本指引核对关系和付费归属。
只问余额或是否欠费时，使用[当前账户状态](arrears-analysis.md)，无需额外查询关系。

## 财务托管如何影响账单

财务托管中，子账号使用云资源，费用由主账号统一支付、开票和结算。子账号余额为零，
不能单独说明没有消费，也不能说明资源无法使用。财务管理是另一种关系：各账号独立
结算，不能把“主子账号有关联”直接解释为主账号代付。

余额为零且仍在使用时，财务托管、已预付资源和账单尚未结算都可能提供线索。
已有可用的余额或账单数据时复用，只补充会改变结论的证据。信用额度为零时，
没有依据把信控额度解释为可继续使用的原因。关系查询说明结算安排，实际扣款、
历史费用归属和资源当前是否可用需要各自的证据。

## 查询并确认关系

使用 `ListFinancialRelation`。缺少适用契约时，一次读取请求规则和业务指引：

```bash
python3 scripts/cost.py schema --action ListFinancialRelation --section request --include-guidance
```

已指定对方账号时，按契约在 body 中使用 `AccountIDSearchList` 缩小范围。
否则查询当前身份可见的关系；确认是否存在某类关系或列出所有成员时使用完整分页：

```bash
python3 scripts/cost.py query --action ListFinancialRelation --body '{"Limit":100,"Offset":0}' --pagination full
```

此 Action 使用 `Limit/Offset` 分页，单页上限 100；没有 `BillPeriod` 和 `NeedRecordNum`。
响应可能以 `Offset=-1` 表示未回显请求偏移，执行器会兼容并按请求偏移推进分页，
继续检查总数、重复页和提前结束；这个值不表示关系记录为空。
已知且仍适用的关系结果可以直接复用。只问付费关系时，无需先查询余额或逐月遍历账单。

有关系记录时，执行器使用相同凭证、profile 和 region 调用只读 `STS GetCallerIdentity`，
按返回的 `AccountId` 与各条关系的主子账号 ID 匹配，结果 `message` 给出当前账号和角色。
采用这个核验结论；身份核验失败时，关系记录仍可使用，但当前角色保持无法确认。

| 字段 | 如何解释 |
|---|---|
| `Relation` / `RelationDesc` | 确认关系类型；财务托管与财务管理分别解释，关系编码不复用账单业务类型编码 |
| `Status` / `StatusDesc` | 确认关系是否生效；未明确生效的记录只说明查到该关系，不能确认当前代付 |
| `Filiation` / `FiliationDesc` | 主/子相对视角，实际看已核验账号 ID 判角色；返回“主”不代表当前登录账号是主账号 |
| `MajorAccountID` / `MajorAccountName` | 关系中的主账号；确认有效财务托管后才解释为统一结算账号 |
| `SubAccountID` / `SubAccountName` | 关系中的子账号；与当前账号身份、用户指定的成员分别核对 |
| `UpdateTime` | 关系记录更新时间，不能据此推算生效时间或历史代付区间 |

编码或状态说明缺失、未知或相互矛盾时，保留原值并说明不能确认的部分，不猜枚举。
当前角色以同一查询凭证核验的账号 ID 为准；用户指定的业务账号不替代登录身份。
不恢复已屏蔽的余额账号字段。
别名和同名账号不能替代账号标识。

## 需要金额时查询账单

确认关系后，继续回答用户尚未解决的金额问题。账单中的 `OwnerID` 表示资源使用方，
`PayerID` 表示支付结算方；财务托管下两者可以不同。仅有两者不同不能证明财务托管，
还应结合关系类型或账单 `BusinessMode`；代销、代售等业务也可能分离使用方与付费方。

指定账期的产品费用使用 `ListBillOverviewByProd`，按契约保留账号筛选并核对返回的
使用方、付费方和业务类型。需要成员、项目或标签的分拆归属时，按实际粒度选择
`ListSplitBillDetail`。沿用[查询与分析](cost-query.md)中的金额口径、币种和分页规则。
主账号的合计可能包含多个成员，不能当作单个子账号的消费。

当前关系不能证明某个历史账期一直由同一主账号代付；历史金额的付费归属以该账期
的账单事实为准。关系表没有金额，不能凭关系记录数计算成员费用。

## 交付与证据不足

确认当前账号是有效财务托管子账号时，说明主账号名称和统一结算安排；余额为零
不单独代表需要向子账号充值。只有关系证据时，不保证资源当前可用，也不确认主账号
资金充足。当前账号是主账号时，按其视角解释成员关系，避免把用户说成被代付方。

正常完成当前账号的完整关系查询且结果为空时，直接说明“当前账号没有财务关系”，
不表述为“无法确认是否有关系”，无需额外查询身份。用户指定筛选或某一页时，
明确说该条件或页范围内没有关系记录。没有财务关系不等于没有消费。
局部单页或 `partial` 结果可以说明已查到的关系，不能排除其他关系。权限失败时说明
无法核实关系；用户已提供的账单事实仍可在其范围内解释，不能用它替代缺失的关系证据。
