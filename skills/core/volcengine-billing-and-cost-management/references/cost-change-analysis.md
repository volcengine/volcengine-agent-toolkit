# 费用变化分析

用于查询费用分布与趋势、解释费用上涨或下降、定位主要变化对象，以及分析金额构成、
用量、价格等因素。
根据用户问题和已有证据选择能力；已有适用结果时直接分析，不要求从产品开始逐级下钻，
也不要求依次调用全部接口。只问趋势、排名或金额时，完成所问内容即可。

## 明确分析范围

复用用户已确认的账号授权范围、产品、项目、地域、实例、计费项、金额口径和比较窗口。
继续下钻时保留上层筛选，不因选择新维度丢失范围或静默改查其他账号。

日期与默认比较窗口沿用[查询与分析](cost-query.md)的规则。使用费用查询数据比较时，
可按接口支持的月、日粒度选择窗口；当前月同期比较需确保两期实际覆盖日期可比。

三个 `QueryCostChange*` 接口均要求明确当期和基期，格式为 `YYYY-MM-01`。
这是三个归因接口的账期约束，不限制费用查询的日粒度能力，也不能据此认定归因接口
支持日级或当前月同期比较。

单账期分析无需基期：按产品、地域等分类查看费用分布，可使用 `ListCostAnalysisOpenApi`；
查看原价、优惠、退款等金额项构成，需查询具有相应字段的账单数据。
不要为调用跨期归因接口擅自添加基期。

## 按问题选择能力

| 要回答的问题 | 可选能力 | 使用条件与结果边界 |
|---|---|---|
| 花了多少、走势如何、哪个分类费用最高，或比较两期单维度费用 | `ListCostAnalysisOpenApi` | 按月或日查询费用趋势及单维度汇总；跨期差额与排名由脚本计算，汇总结果本身不证明变化原因 |
| 两账期应付变化主要由哪些对象贡献 | `QueryCostChangeDimensions` | 维度定位支持产品、地域、实例、项目、计费项；保留上涨与下降对象及候选结果的覆盖范围 |
| 某计费项的原价、优惠、退款等金额项如何变化 | `QueryCostChangeAmountComponents` | 需要已知计费项；只解释实际返回的金额项，不假设结果包含完整构成 |
| 某计费项是用量、单价还是其他因素驱动 | `QueryCostChangeDrivers` | 需要已知计费项，分析原价变化，不能直接作为应付变化的因子贡献 |

`ListCostAnalysisOpenApi` 提供费用数据，三个归因接口提供特定比较范围内的变化分析。
同一个“哪个产品涨得最多”问题，可以用可比汇总数据计算，也可以用维度定位结果回答；
已有结果满足用户问题且范围、口径、覆盖和时效适用时直接复用，无需重复调用两类接口。
需要进一步解释金额项或用量、单价时，再选择对应归因能力或明细取证。

已知计费项且问题明确时，直接选择对应能力。缺少计费项时，可按已有范围查询或用
维度定位补齐；无法唯一确定分析对象且会改变结论时再追问。用户指定地域或实例时，
可直接从该维度分析。只问变化对象时，无需自动继续金额构成或因子分析。

### 费用查询与归因的组合

使用 `ListCostAnalysisOpenApi` 的典型问题是“最近几个月费用走势如何”“本月各产品费用
占比多少”“按地域看两个月分别花了多少”。使用前按[查询与分析](cost-query.md)
核对时效、字段粒度和查询范围；不满足需求时选择对应账单数据源。请求字段、分页、
数据采集与通用校验规则统一以该文档和接口契约为准。

跨接口组合时核对金额口径和比较对象：费用查询可选择账单或摊销成本口径，
但三个归因接口的固定口径不随之改变。摊销成本变化不能直接由账单应付或原价归因
解释；不同窗口、筛选或时效的结果也不能直接串成同一条归因证据。

例如，只问“按产品看本月费用和上月差额”时，可查询单维度汇总并计算后交付；
问“应付增量主要集中在哪些产品或实例”时，可选择维度定位；已给计费项并问
“是不是用量涨了”时，可直接选择原价驱动因子分析，并说明它与应付金额的口径区别。
这些是按问题选用的示例，不构成固定调用顺序。

### 接口参数与金额口径

以下为四个接口的实际业务请求字段摘要；完整类型、枚举和嵌套结构以接口契约为准。
接口字段的名称和编码分别使用，不将某一接口的参数直接套到另一个接口。

| 接口 | 关键参数 | 金额口径 |
|---|---|---|
| `ListCostAnalysisOpenApi` | `BeginTimeStr`、`EndTimeStr`、`TimeGranularity`、`ClassifyDimension`、`CostType`；筛选和分页按契约 | `CostType=0/1/2` 为账单原价/折后价/应付，`4/5/6` 为成本本期已分摊的对应金额 |
| `QueryCostChangeDimensions` | `CurrentPeriod`、`BasePeriod`、`CandidateDimensions`、`Metric`，可选 `Filters` | 应付金额，固定 `Metric=3` |
| `QueryCostChangeAmountComponents` | `CurrentPeriod`、`BasePeriod`、`Metric`、`Filters.charge_item_code` | 应付金额变化的金额项分析，固定 `Metric=3` |
| `QueryCostChangeDrivers` | `current_period`、`base_period`、`Metric`、`filters.charge_item_code` | 原价金额，固定 `Metric=original_bill_amount` |

三个归因接口还需满足以下条件：

- 维度定位的 `CandidateDimensions` 只传一个值，可选 `product`、`charge_item_code`、
  `instance_no`、`region_code` 或 `project`。
- `Filters` / `filters` 仅接受上述五类 key，值为字符串。金额构成与因子分析必须包含
  已知的 `charge_item_code`，并保留其他范围筛选。
- 账号由当前认证上下文确定，不向归因请求添加 `account_id`、`AccountID` 或凭证。

`ListCostAnalysisOpenApi` 的 `Filters` 是另一种请求结构，不能复用归因接口的筛选对象；
其应付金额编码为 `CostType=2`，与归因接口的 `Metric=3` 不同。

## 计算与解释规则

所有数值计算使用脚本或计算工具。金额精度、币种、单位、缺失值、数据关联及范围核验
继承[查询与分析](cost-query.md)第 4 节的规则。

- 对齐金额口径、账号、筛选、时效与比较窗口后，计算差额 `本期 - 基期`。
  基期大于零时才使用常规增长率；缺失金额保持未知，不当作零。
- 比较对象时保留新增、消失、上涨和下降项。确认两期采集完整且对象确实不存在后，
  才可将该侧视为零；缺页、失败或缺字段不能作为对象不存在的依据。
- 自行计算贡献比例时，使用同一口径和范围的总差额作分母。总差额为零时不算比例；
  涨跌抵消时，贡献可能为负或超过 100%。接口返回的比例先核实其分母定义，
  不根据字段名假定与自行计算的比例一致。
- 根据变化金额选择主要对象，同时说明 TopN 或候选结果的覆盖范围；局部候选不能
  冒充全量，也不能因某因素未返回就认定已排除。
- 金额项可能包含原价、折后价等不同计算阶段，不能直接相加当作费用构成恒等式。
  只使用已有契约明确的金额关系；保留退款、冲正等负数，说明其实际影响。
- Drivers 返回的用量、单价和其他因子贡献解释的是原价变化。应付与原价分开报告；
  不能将原价因子贡献直接写成应付涨幅贡献，也不能跨口径累计贡献。
- 用量与应付同步变化只说明关联。解释驱动时核查相同对象、计费项、单位、可比价格
  和优惠；不同计费项或单位分别分析，不用单价乘用量猜测完整计费公式。

## 补充取证与结束分析

线索指向资源包或代金券时，按需进入[账户欠费与抵扣核查](arrears-analysis.md)中的
相应抵扣分析，无需先查当前账户状态。需要核对账务来源差异时使用
[聚合对账与观察性比较](cost-reconciliation.md)。

成功调用只证明取得声明范围内的结果，不证明数据全量、账期最终或原因已证实。
查询失败、授权失败、接口不可用和证据不足均不解释为零费用。已有足够证据回答用户
问题时停止；需要补查时围绕尚未回答的问题选择能力，不设固定调用序列或状态机协议。

## 回答方式

先说明费用变化及主要对象，再给关键证据和必要限制。按用户所问覆盖：变化了多少、
主要变化在哪里、哪些驱动有证据、哪些尚未核实。金额按币种分别表达；比例说明口径。
API 名称和底层字段通常留在复现材料中，不作为业务回答主体。

只有关联证据时可表述为：“本期应付比基期增加……，主要增量来自……；同一计费项
用量增加……。价格或优惠变化尚未核实，目前只能确认用量与应付同步上涨。”
填入实际计算结果；获得更强证据时按其支持范围解释，不用候选原因列表代替结论。
