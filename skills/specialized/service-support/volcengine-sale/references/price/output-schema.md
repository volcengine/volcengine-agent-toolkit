# 询价结果输出结构

询价结果的**统一数据结构**。先按本结构整理出完整字段，再按「文字渲染规则」输出为表格，**不得跳过结构直接撰写文案**。

> 用户未明确商品、需要返回商品清单时，用 [common/product-list-schema.md](../common/product-list-schema.md) 的 `ProductList` 结构。

## 字段来源标记

沿用 [common/product-list-schema.md](../common/product-list-schema.md) 的约定：`[询价]` 询价接口返回、`[商品]` 商品接口返回（**当前不可用**）、`[流程]` 流程内已确定、`[模型]` 允许模型生成。

**`[询价]` 字段一律原样透传**：不改写、不四舍五入、不换算币种、不做任何算术加工。

## 询价结果结构

结构是**三层**：`Scenarios[]` 是场景，`Items[]` 是场景内按商品分组的明细，`Total` 是该场景的合计。一个场景对应一个方案，一组商品配置对应一个 `Item`。

**本期只产出一个场景**，`Scenarios[]` 恒为 1 个元素；下一期支持同时给出多个场景，每个场景在前端是一个独立 tab。

```
QuoteResult
├── Currency                       [询价] 币种，全局统一，取自询价接口返回的 Currency
├── Scenarios[]                    场景列表，本期恒为 1 个
│   ├── ScenarioName               [模型] 场景名称，如「低成本问答」「多模态理解」
│   ├── ScenarioDesc               [模型] 场景说明，说明该场景的适用范围与取舍
│   ├── Items[]                    该场景内的商品配置列表，至少 1 个
│   │   ├── Product                [流程] 商品编码，内部字段，不渲染给用户
│   │   ├── ProductName            [本地] 商品名称，取自商品清单
│   │   ├── ConfigurationCode      [询价] 配置编码
│   │   ├── ConfigurationName      [商品] 配置名称；缺失时显示 ConfigurationCode
│   │   ├── PaymentMethod          [流程] 付费类型：预付费 / 后付费
│   │   ├── OriginalAmount         [询价] TotalOriginalAmount，本商品配置的总刊例价
│   │   ├── DiscountAmount         [询价] TotalDiscountAmount，本商品配置的总折后价
│   │   ├── UsageInput             [流程] 用户提供的用量属性值与购买时长，原样记录，不换算
│   │   └── ChargeItems[]          计费单元明细
│   │       ├── ChargeItemCode     [询价] 计费项编码
│   │       ├── ElementName        [商品] 计费单元名称；缺失时显示 ChargeItemCode
│   │       ├── FactorDesc         [商品] 属性值描述，如「输入长度 [0,32] 千 token」；缺失时省略
│   │       ├── BillingMethodName  [商品] 计费方式名称，如「按加和量实时结」；缺失时省略
│   │       ├── Quantity           [询价] Quantity
│   │       ├── EstimatedUsage     [流程] 用量属性值，取自入参 Count
│   │       ├── EstimatedDuration  [流程] 购买时长，取自入参 UseDuration
│   │       ├── UsageUnit          [商品] 用量单位，**当前不可用**；不得自行推断
│   │       ├── Price              [询价] Price
│   │       ├── OriginalAmount     [询价] 该计费项原价
│   │       ├── DiscountAmount     [询价] 该计费项折后价
│   │       └── DiscountDetail     [询价] DiscountType / DiscountPrice
│   └── Total                      **本场景**询价合计，仅汇总本场景 Items 的金额
│       ├── OriginalAmount         [计算] 本场景各 Item 的 OriginalAmount 之和
│       ├── DiscountAmount         [计算] 本场景各 Item 的 DiscountAmount 之和
│       └── ItemCount              [流程] 本场景参与合计的商品配置项数
├── RiskNotes[]                    [模型] 风险提示
└── Disclaimer                     固定文案：估算值，以实际使用出账为准
```

合计**只存在于场景层**。`QuoteResult` 顶层**不设跨场景总金额**：不同场景是同一需求的互斥备选方案，把它们相加没有业务含义。

`Currency` 全局只出现一次。跨商品时各次调用返回的币种一致，取任一即可；若出现不一致，说明存在跨境商品混询，如实说明并按商品分别展示金额，不做合计。

下一期返回给前端的 JSON 沿用这个结构，本期的文字表格是它的渲染形态。

### 金额字段的硬约束

- `Items[].OriginalAmount` 与 `Items[].DiscountAmount` **只能取询价接口返回的 `TotalOriginalAmount` 与 `TotalDiscountAmount`**，且取自该商品那次调用的返回值。
- **禁止将各计费单元的 `Price` 相加作为费用**：不同计费单元的计量口径不同，相加无业务含义。
- `ChargeItems[].Price` 只在明细中逐条展示，不做任何汇总。
- 金额字段为 `***` 时按 [errors.md](./errors.md) 的「折后价被掩码」处理，原样保留。

### 合计的计算

`Total` 为**本场景内**各 `Item` 的 `OriginalAmount` 与 `DiscountAmount` 分别求和。付费类型与计费方式不同的项目一并汇总，不作区分。

**合计的范围严格限定在单个场景内**：不得跨场景求和，也不得在顶层再输出一个总金额。

**必须通过脚本计算，且使用 `Decimal` 按字符串求和**。浮点相加会产生精度误差（`3.1555 + 1.7601` 得到 `4.9155999999999995`），该尾数会被当作真实金额输出：

```bash
python3 -c "
from decimal import Decimal
print(sum(map(Decimal, ['3.1555', '1.7601'])))
"
```

金额取自接口返回的字符串，**原样传入，不得先转为 float**。小数位与各 `Item` 保持一致，**不得四舍五入**。

两种例外：

| 情况 | 处理 |
|---|---|
| 任一金额为 `***` | 被掩码的值无法参与求和。合计仅汇总可见项，并注明「不含 N 项因权限受限不可见的金额」 |
| 任一商品询价失败 | 仍输出合计，但**必须标明覆盖范围**（「共 N 项配置」按实际成功数写） |

### Scenario 与 Item 的数量

- **本期 `Scenarios[]` 恒为 1 个元素**，`ScenarioName` 与 `ScenarioDesc` 由模型生成，不影响询价入参。**不得自行拆分为多个场景**。
- `Item` 数由**用户实际提供的商品配置组数**决定，同一场景内的全部商品配置都放进该场景的 `Items[]`。
- **不得由模型自行构造配置组合**：商品、配置与计费项编码必须来自用户提供。

## 文字渲染规则

**一个场景渲染为一张表**，不论涉及几个商品、几组配置。表内按商品配置分组，每组是「商品配置行 + 计费单元组」两层：

1. **抬头**：场景名称与场景说明（一句话），置于表格上方的正文中。
2. **商品配置行**：表头为「商品名 / 配置名 / 总刊例价 / 总折后价 / 付费类型」，其下一行是该配置的取值。
3. **计费单元组**：紧接着**再写一行表头**（加粗），五列依次为「计费单元」「用量 / 时长」「刊例价」「折后价」「优惠类型」，其下每行一个计费单元。
4. **多个商品配置**：第二组及之后的商品配置，在上一组计费单元行下方**重复第 2、3 步的两行表头**，继续往下排，**始终在同一张表内**。
5. **合计行**：表格最后一行，首列写「**预估费用合计**」并注明项数，金额填入总刊例价与总折后价对应的列。该行**始终输出**，单商品场景同样保留。合计范围是**本场景**，本期只有一个场景，即全部结果。

两组表头**列数必须一致**，列数较少的一组用空单元格补齐。

列顺序按「金额列上下对齐」排定：刊例价与折后价两组一一对应；付费类型置于末列，与优惠类型同列。**不得将付费类型插入金额列之前**。

单商品单配置：

```
| 商品名 | 配置名 | 总刊例价 | 总折后价 | 付费类型 |
|---|---|---|---|---|
| 云服务器 | ecs.g3i-alb.2xlarge | 4.9156 | 4.9156 | 后付费 |
| **计费单元** | **用量 / 时长** | **刊例价** | **折后价** | **优惠类型** |
| ecs.g3i-alb_2xlarge_ap-southeast-1 | 1 / 1 | 3.1555 | 3.1555 | 无优惠 |
| ecs.g3i-alb_2xlarge_cn-wulanchabu | 1 / 1 | 1.7601 | 1.7601 | 无优惠 |
| **预估费用合计（共 1 项配置）** | | **CNY 4.9156** | **CNY 4.9156** | |
```

跨商品时同样只有一张表，第二个商品的两行表头接在上一组下方，合计行在最末：

```
| 商品名 | 配置名 | 总刊例价 | 总折后价 | 付费类型 |
|---|---|---|---|---|
| 云服务器 | ecs.g3i-alb.2xlarge | 3.1555 | 3.1555 | 后付费 |
| **计费单元** | **用量 / 时长** | **刊例价** | **折后价** | **优惠类型** |
| ecs.g3i-alb_2xlarge_ap-southeast-1 | 1 / 1 | 3.1555 | 3.1555 | 无优惠 |
| **商品名** | **配置名** | **总刊例价** | **总折后价** | **付费类型** |
| 火山方舟 | Doubao_Seed_2.1_turbo | 0.015 | 0.015 | 后付费 |
| **计费单元** | **用量 / 时长** | **刊例价** | **折后价** | **优惠类型** |
| Doubao_Seed_2.1_turbo_infer_output_cn-beijing_realtime | 1 / 1 | 0.015 | 0.015 | 无优惠 |
| **预估费用合计（共 2 项配置）** | | **CNY 3.1705** | **CNY 3.1705** | |
```

合计行的金额与上方商品配置行的金额**列对齐**，第 2、5 列置空。

### 用量 / 时长列

计费单元组**固定展示「用量 / 时长」一列**，格式 `<用量> / <时长>`（如 `1 / 1`），取自入参 `Count` 与 `UseDuration`。

- **两个值并列展示，不作取舍**。实际生效的字段取决于计费方式，而计费方式名依赖尚未对接的商品接口，流程内无法判定。
- **两个值均不带单位**。不得为数值补充「台」「千 token」「小时」等单位，不得将该列改名为单一的「预估用量」或「购买时长」，不得省略其中任一值。

### 其他细节

`FactorDesc` 可取到时，写入计费单元名称的同一单元格，用 `<br>` 换行置于名称下方。

上例中「计费方式」列因 `BillingMethodName` 不可取而整列省略，「配置名」因 `ConfigurationName` 不可取而降级显示配置编码。**按实际可取到的字段决定列的去留，不保留空列，不填充占位符**。

单组计费单元超过 5 行时仅展示前 5 行，并在表后注明「共 N 条，回复"展开明细"查看全部」。

最后统一输出一次 `RiskNotes` 与 `Disclaimer`，不在每个商品下重复。

### 五条反模式

- **不得按商品拆分为多张表**：同一场景内的跨商品对客仍属一次询价，结果必须汇总在同一张表内。
- **不得输出为两张表**（商品配置一张、计费单元明细另一张）。两组必须在同一张表内，中间不得插入空行或标题。
- **不得将两组表头合并为一行宽表头**：商品名、配置名随每个计费单元行重复或置空，会丢失父子层级。
- **不得渲染为「项目 / 内容」两列的纵向键值表**。
- **不得输出跨场景的总金额**：合计只属于单个场景。本期仅一个场景，不存在跨场景汇总的情形。

## 字段缺失的处理原则

`[商品]` 类字段当前不可用，渲染时：

- **`ProductName`** 取自商品清单，始终有值，直接展示中文名。
- 配置名、计费单元名缺失时 → 展示对应编码，不留空。
- 计费方式名、属性值描述缺失时 → **整列省略**。
- 用量单位缺失时 → 用量与时长**并列展示数值、不带单位**。
- 任何情况下都**不得由模型推断填充**。将编码翻译为中文名、根据编码猜测计费方式、为用量数值补充单位，均属于生成事实，违反铁律。
