# price 动作：询价流程

用户需要了解价格、计费方式或预估费用时执行本流程。支持**新购**场景的预付费与后付费询价，所有商品共用本流程。

## 铁律（执行前必读，不得违反）

- 任何具体金额、单价、费率**必须来自询价 OpenAPI 的返回值**，禁止由模型生成、推算、补全或"参考同类商品"。**唯一例外**是合计行，见 [output-schema.md](./output-schema.md) 的「合计的计算」。
- 模型只允许生成两类内容：**计费规则解释**、**场景说明**。用量与时长一律取自用户提供的值，**不做换算、不做推断**。
- 计费规则解释必须附带产线文档来源链接；无可引用文档时不作解释。
- 任何询价结果必须标注"估算值，以实际使用出账为准"。
- 无法获得接口返回值时，**降级到价格计算器**，不得以任何形式输出未经接口确认的金额。

## 步骤 1：付费模式判定

| 用户表述 | 判定 | 使用的 Action |
|---|---|---|
| 包年包月、买一年、买 3 个月、预付费、订阅、subscription、按年、按月 | 预付费新购 | `QueryPriceForSubscription` |
| 按量、按需、按小时、用多少算多少、后付费、pay-as-you-go、spot | 后付费 | `QueryPriceForPayAsYouGo` |
| 续费多少钱、renew、续一年 | 续费询价 | 本流程仅支持新购询价，**不得用新购询价代替续费询价**；引导用户前往控制台费用中心的续费页查看 |
| 未表明 | **必须向用户确认** | 在步骤 5 的确认环节一并问清，**不得自行推定** |

## 步骤 2：商品识别

按 [common/product-catalog.md](../common/product-catalog.md) 的商品清单，用用户提供的商品名匹配对应行。

- 命中且唯一 → 进入步骤 3。
- 命中多个 → 列出全部命中的商品名请用户确认。
- 未命中清单 → 说明该商品暂不支持通过命令行询价，转入降级流程。**不得猜测或拼写清单外的商品编码。**

用户单次询问多个商品时逐个匹配。部分未命中**不中断整个流程**：已命中的商品正常询价，未命中的单独说明并引导至价格计算器。

### 用户未明确商品时

用户表达了询价意图但未指明具体商品（例："火山引擎有哪些 AI 商品"）时，先返回商品清单供其选择：

- 按 [common/product-list-schema.md](../common/product-list-schema.md) 的 `ProductList` 结构组织并渲染。
- 用户按分类提问时，仅列出该分类下的商品。
- 清单内容只能来自商品清单文件，**不得由模型补充未收录的商品**；无匹配时如实说明并引导用户前往火山引擎官网产品页浏览。

## 步骤 3：配置与计费项确认

`ConfigurationCode` 与 `ChargeItemCode` 均为**必填、无默认购买逻辑**：

```
① 用户已提供这两项编码             → 进入步骤 4
② 用户无法提供 / 追问 2 轮仍未获得 → 转入降级流程
```

- 计费项编码不允许猜测、留空或以相近值代替。
- 用户提供的是**自然语言配置描述**（如"4 核 8G 的云服务器"）而非编码时，**不属于**分支 ①，仍按分支 ② 处理。
- 追问需**一次问全**：付费模式与缺失的编码合并为一条消息。整个 price 流程追问总数 ≤2 次。用量属性值与购买时长**不纳入追问范围**，缺失时按步骤 4 取默认值。

## 步骤 4：用量属性值与购买时长

| 字段 | 含义 | 填法 |
|---|---|---|
| `Count` | **用量属性值** | 用户已提供时取用户值；未提供时默认 `1` |
| `UseDuration` | **购买时长** | 用户已提供时取用户值；未提供时默认 `1` |
| `Quantity` | 购买数量 | 用户已提供时取用户值，取值范围 `[1, 2000]`；未提供时默认 `1` |

| 接口 | 计费方式 | `Count` | `UseDuration` |
|---|---|---|---|
| 后付费 `QueryPriceForPayAsYouGo` | 按配置 | 用量属性值 | 购买时长 |
| 后付费 `QueryPriceForPayAsYouGo` | 按用量 | 用量属性值 | 可不传 |
| 预付费 `QueryPriceForSubscription` | — | 用量属性值 | 购买时长 |

**两个字段一律都传**，不因判定计费方式而省略其一。

### 取默认值 1 的处理

`Count` 或 `UseDuration` 缺任一项时**取默认值 `1`，不单独追问**，直接带入步骤 5 的确认环节：

- 用户确认 → 按 `1` 发起询价。
- 用户给出具体数值 → **以用户提供的值为准**，修正后重新确认。

默认值必须在确认信息中**显式标注为默认值**。

### 不做用量换算

本期**不做任何用量换算**。用户提供「每天 50 万次请求」「用 200 万 token」这类**业务量描述**时，按未提供处理，取默认值 `1`，并在确认环节请用户直接提供用量属性值。

`Count` 的含义由该计费项的用量单位决定，同一个数字在不同商品下含义不同（`2` 在实例类是 2 台，在 token 计费类是 2 千 token）。本期**不推断、不换算、不校验单位**。

「按平均量月结」与「按峰值」两类计费方式**不支持接口询价**。用户明确说明属于这两类时，告知暂不支持并转入降级流程；无法判定时正常发起询价，由接口报错后再降级。

### 取值合法性前置自查

- `Count` 与 `UseDuration` 均**不得为 0 或负数**。用户提供 0 或负数时，说明取值不合法并请其修正，**不得自行改为 `1`**。
- 属性值取值方式为**范围值**时，超出商品定义范围会报错。预付费下 `Count` 为 `0` 会返回 0 元且不报错，该结果无效，**不得作为真实报价展示**。
- 预付费的**枚举值**可为空，且不参与询价。

## 步骤 5：询价前确认（不得跳过）

```
【询价信息确认】
  商品：<商品名称>（<商品编码>）
  配置编码：<configuration-code>
  计费项编码：<charge-item-code>
  付费类型：预付费 ／ 后付费
  购买数量：<quantity>
  用量属性值：<count>          ← 取默认值时标注「默认 1，如需修改请告知」
  购买时长：<use-duration>     ← 取默认值时标注「默认 1，如需修改请告知」

  以上信息是否正确？确认后我将发起询价。
```

- **付费类型未经用户确认时，一律不得自行推定**。预付费与后付费调用不同接口，选错将给出误导性金额。
- 用量属性值与购买时长**原样展示**，不做换算、不加单位；取自默认值的项必须标注。
- 用户指出任一项有误 → 以用户提供的值为准，修正后重新确认。
- 用户单次提供多组配置或多个商品 → 每组各列一份，**一次性列全并统一确认**，不按商品拆分为多轮。

## 步骤 6：调用询价接口

服务 `billing`，Version `2022-01-01`，POST。两个 Action 均为 `Query*` 只读操作，可直接执行，但仍须先完成步骤 5 的信息确认。

子用户需具备 `BillingCenterFullAccess` 或 `BillingCenterReadOnlyAccess` 权限策略。接口 QPS ≤10。

两个接口**入参结构完全相同**，商品编码字段名都是 `Product`（不是 `ProductCode`），时长字段都在 `ConfigList` **内层**。

### 多商品：按商品各调一次，对客当作一次询价

`Product` 为单值，接口**不支持单次查询多个商品**。用户单次询问多个商品时，按商品拆分、逐个调用，再将结果汇总为一份输出。

- **调用过程不对客说明**：不提及「需要分多次调用」，也不按商品分段汇报结果。
- 同一商品的多个配置计费项合并至同一次调用的 `ConfigList`。
- 多次调用之间需控制频率，QPS ≤10。
- 单个商品调用失败时，其余商品的结果正常输出，并如实说明失败的商品与失败原因。
- 结果按 [output-schema.md](./output-schema.md) 的渲染规则**汇总为一张表**。

### 6.1 后付费：QueryPriceForPayAsYouGo

```bash
ve billing QueryPriceForPayAsYouGo --body '{"Product":"<product>","ConfigList":[{"ConfigurationCode":"<config-code>","ChargeItemCode":"<charge-item-code>","Quantity":1,"Count":"<count>","UseDuration":1}]}'
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `Product` | string | 是 | 商品 code，单商品，不支持批量 |
| `ConfigList` | array | 是 | 规格列表，单次最多 50 组 |
| `ConfigList[].ConfigurationCode` | string | 是 | 配置编码 |
| `ConfigList[].ChargeItemCode` | string | 是 | 计费项编码，无默认购买逻辑 |
| `ConfigList[].Quantity` | integer | 是 | 数量 |
| `ConfigList[].Count` | string | 是 | **用量属性值** |
| `ConfigList[].UseDuration` | integer | 否 | **购买时长**。按配置计费时必传，按用量计费可不传；本流程**一律传入** |

### 6.2 预付费：QueryPriceForSubscription

```bash
ve billing QueryPriceForSubscription --body '{"Product":"<product>","ConfigList":[{"ConfigurationCode":"<config-code>","ChargeItemCode":"<charge-item-code>","Quantity":1,"UseDuration":1,"Count":"<count>"}]}'
```

与后付费的差异：

- `ConfigList` 单次最多 **20 组**（后付费为 50 组）。
- `ConfigList[].UseDuration` 在接口层面即为**必填**。
- 仅支持预付费规格的**新购**场景询价。

### 出参（两个接口一致）

`Currency`（CNY）、`TotalOriginalAmount`（总刊例价）、`TotalDiscountAmount`（总折扣价）、`CalSerialNo`、`ConfigList[]`（含 `ConfigurationCode`、`ChargeItemCode`、`Quantity`、`OriginalAmount`、`DiscountAmount`、`Price`、`DiscountDetail{DiscountType, DiscountPrice}`）。

## 步骤 7：结果呈现

按 [output-schema.md](./output-schema.md) 的 `QuoteResult` 结构整理结果，再渲染为文字表格。**先填充结构，后执行渲染**。

核心约束（详见 schema）：

- `[询价]` 字段原样透传，不改写、不四舍五入、不换算币种。
- 单个商品配置的估算费用只取接口返回的总额，**不得把各计费单元单价相加**；表末的合计行对**本场景内**各商品配置的总额做纯汇总，用脚本计算。
- 商品名取自商品清单，始终展示中文名；配置名与计费单元名缺失时展示用户提供的对应编码；其余 `[商品]` 类字段缺失时整列省略，**不得由模型推断填充**。
- 本期只输出**一个场景**，同一场景内的跨商品结果汇总为一张表。
- 风险提示与"估算值，以实际使用出账为准"两部分必须输出。

## 执行失败

命令实际返回错误时，按 [errors.md](./errors.md) 处理。降级至价格计算器的触发条件与对客话术同见该文件。
