## 路径选择

用户同意只要部分结果，或暂时无法导出全部日志、已有结果仍有用时，可以提供检查过的文件。必须明确说明文件包含哪些日志、还有哪些未导出，不能称为全量。

用户要求导出日志，不代表同意停止投递或删除资源。这些操作需要另外明确授权。

此前已经在查询或导出日志，用户说“只导出了当前页”或“只有 200 条”时，继续导出其余匹配日志。如果用户明确只想排查控制台问题或了解操作步骤，就不自动下载。

1. 用户只要已查到的日志，就保存这些日志。用户要全部日志时，根据筛选条件和日志数量选择导出方式。
2. 查询时间在近 90 天内、基础检索支持所需条件，且已知结果不超过 200 条时，按 event-query.md 使用基础导出，检查 `Complete` 和 `HasMore`。这种情况不必先查 TLS／TOS。
3. 不知道日志数量，但基础检索支持所需条件时，可以先查少量结果或尝试基础导出。结果完整就提供文件；达到上限或 `HasMore=true` 时，记录未导完的情况，继续查找并下载 TLS／TOS 中的日志，不把已有文件称为全量。
4. 已知超过 200 条、基础检索不支持所需条件、时间超过 90 天，或已有符合需求的 TLS／TOS 日志时，直接检查已投递的日志。不必为了估算要翻多少页单独统计；需要核对是否导出完整时再统计。
5. TLS／TOS 中有可用日志就直接下载。确认缺少所需日志且支持补投时，按 backfill-delivery-tasks.md 准备方案并请用户确认。无法补齐时，说明哪些时段或事件无法取得。

## 查找已投递的日志

先根据已有信息查找，不要求用户逐项提供资源名称或 ID：

1. 优先检查用户指定或此前已知的跟踪、TLS 日志主题和 TOS 路径。核实账号、权限、日志字段，以及是否包含所需时段和事件，不仅凭资源名称判断。
2. 列出本次账号能查看的跟踪，包括相关组织跟踪，从配置中找到 TLS 日志主题或 TOS 存储桶。当前配置和开启时间只能帮助查找，不能证明过去一直在投递。
3. 找不到跟踪，或其中的日志不包含所需时段和事件时，继续检查历史补投任务、已知下载任务和此前提供过的文件记录。旧任务可以帮助找到日志保存位置，但不能证明那里也有本次要查的日志。
4. 在已知地域、日志项目或存储桶中，按现有权限查找。查看主题的日志保留时间、少量日志样本，或指定前缀下的对象列表。不遍历所有账号和地域；确实需要扩大查找范围时，先说明原因。
5. 主题或存储桶中的日志可以直接下载时，不因原跟踪已删除就重新创建跟踪。需要合并多个主题或桶中的日志时，核对各自的时段和事件，避免重复。仍无法确定所属账号、权限或保存位置时，再一次问清缺少的信息。
6. 核实日志来源账号、存储资源所属账号、地域、保留时间、事件发生时间、写入时间、采集的事件范围和访问权限。能够访问主题，或日志中出现某个账号，不能代替对实际调用身份的检查。

### 原始下载后本地筛选

没有所需索引时，仍可能通过下载原始日志完成导出。如果原始事件中有可靠的筛选字段，且下载量、传输和保存成本合适，可以先下载包含全部匹配事件的日志，再在本地按账号、EventTime、事件源、资源和读写条件筛选。不因缺索引就自动新建主题、重新建立索引或补投。

- 先确认下载的日志能包含全部匹配事件，不能为了简化查询漏掉事件源或条件。保留原始事件字段；同一主题中还有其他业务日志时，先识别哪些是审计日志。
- 核对写入时间和 `EventTime`。补投日志按实际写入的时间段下载，再按事件发生时间筛选。
- 筛选后核对账号、条件、时区和范围边界，必要时按 EventID 去重并记录数量。
- 分别检查日志是否全部下载、本地筛选是否正确。只下载了一部分日志，即使筛选正确也不是全量。需要明显扩大下载范围、增加费用或改变数据保存方式时，先说明影响，并确认用户授权包含这些操作。

### TOS 已投递日志下载

所需日志已投递到 TOS 时加载 `volcengine-tosutil`，分别核对调用身份、资源账号、桶地域与权限，在指定前缀下查找实际的审计日志对象。核对投递路径、对象时间与事件时间、分片清单和分页结束状态，不能只下载首屏对象。下载后验证压缩包与内容可读性，按原账号、EventTime 和筛选条件生成结果，避免混入其他账号或重复日志。无法确认对象是否列全、日志是否包含所需历史时段时，说明尚未核实的部分，不因存储桶存在就称日志完整。


## 默认路径：TLS 离线下载任务

需要从 TLS 导出全部或大批量日志时，优先使用 TLS 离线下载任务。日志已在 TLS 中时直接下载；缺少所需的已投递历史日志且符合补投范围时，先按 [backfill-delivery-tasks.md](backfill-delivery-tasks.md) 补投，完成后再下载。重新补投不能解决下载任务超限。

通过 `volcengine-tls` 创建下载任务、查询状态并获取文件；具体命令和参数遵循该技能。

1. 确定账号、TLS 日志主题、查询条件和起止时间，使用已核实的 TLS 身份、地域和服务地址。导出此前查询的结果时，沿用当时的起止时间，不重新计算“最近几天”。时间单位由程序转换。
2. 按 [高级检索](advanced-query.md) 检查日志字段和索引，读取少量原始日志，再用准备下载的查询语句试查，确认它能执行、筛选条件也符合用户要求。同一主题和条件已经验证过，且验证结果仍适用时，无需重复。没有查到样本时，结合索引、原始字段和日志保存时段判断，不能直接认为查询正确或没有历史日志。字段无法直接检索时，按“原始下载后本地筛选”处理，确认下载范围不会遗漏匹配事件、本地筛选有可靠依据，不擅自删条件或改索引。
3. 按 `volcengine-tls` 的接口说明准备下载请求，并先检查参数。这个本地检查不会实际查询日志，不能代替上一步的试查。用户明确要求导出时，可以创建相同范围的下载任务，但不代表可以自动创建跟踪、补投或修改主题。任务名称不能重复，并写明下载普通日志还是分析结果、文件格式、压缩方式和条数上限。不要照搬示例中的小 `Limit`，导致只下载一部分。导出全部日志时，不允许服务返回部分查询结果；“完全精确查询”选项按账号实际支持情况设置。
4. 创建后保存 `TaskId`、日志主题和完整请求。返回结果不明确时，按主题、任务名和任务 ID 查询，必要时翻页查找，不重复创建。定期查询任务状态，直到完成、失败或取消。生成中继续等待，失败或取消时说明原因。当前会话无法继续等待时，保存任务信息和最新状态，方便之后继续；没有后台执行能力或相应授权时，不承诺会在后台继续。
5. 文件生成后，通过 `volcengine-tls` 获取下载地址并下载。链接过期时重新获取地址，不重新创建任务。不长期保存带签名的下载地址，也不将其作为公开链接分享。确认文件已下载且可以读取后，再提供给用户。创建任务或取得链接都不等于下载完成。
6. 核对任务状态、实际条数和文件内容，检查是否因上限等原因只返回了部分日志。文件生成中断、返回部分结果或条数达到 `Limit` 时，不能仅凭有文件就称为全量。需要分批下载时，保持原查询条件，由程序拆分原时间范围，并按接口对起止时间的规定避免重叠和遗漏。同一时间点的日志仍超限、且无法可靠拆分时，说明限制，不反复重试。
7. 分批下载时，逐个确认任务完成、文件可读，再汇总时段、条数和文件列表。某一批失败，只重新处理这一批，不重复合并已有文件。确认所有批次包含原时间范围、且没有少返回日志后，才能说全部下载完成。仍需单独说明历史日志是否已完整投递。

[TLS 下载日志文档](https://docs.volcengine.com/docs/TorchLogService/Downloadlogs?lang=zh)规定：原始日志单任务最多 2000 万条且不超过 20 GiB，分析结果最多 100 万条且不超过 2 GiB；大数据量推荐缩小时间范围、分多次下载。执行时核对当前限制；超限可能仅生成部分文件。下载任务记录及文件保留 1 天，生成后及时下载。下载期间不要修改查询依赖的索引。

## 备用路径：检索分页导出

适用于用户明确选择分页导出，或离线下载不可用的情况。按 `volcengine-tls` 当前接口说明执行，固定账号、主题、绝对时间和查询条件。

- 普通日志逐页核对扫描状态与续页标记，扫描完整且到达末页后再汇总文件。达到上限或尚未扫描完时，保存已取得的结果，说明还缺哪些部分，再继续查询或改用其他导出方式。
- SQL 分析按语句及接口限制解释结果范围，保留用户的 limit/offset。
- 校验实际文件可读、条数和范围匹配。工具只返回文件路径时读取文件；确认全部导出前，同时检查扫描是否完成、分页是否已到末页。

## 统计与核对

- 用户只要统计结果时，已有 TLS 日志可满足条件和时间范围的，直接统计，无需先下载。用户要求导出后分析的，文件校验完成后继续分析。
- 统计时说明账号、时间范围、筛选条件和计数单位（事件、请求、资源或 IP）。按 EventID 去重时同时核对账号；缺失 ID、内容冲突或无法解析的记录单独说明。IP 统计区分有效地址、缺失和非地址值。
- 比较控制台、API、TLS/TOS 的数量时，先确认时间、条件、事件类型和去重方式一致，再检查是否漏查分页、达到条数上限，或缺少某些时段的日志。
- 有已知事件或 RequestID 时，核对导出结果是否包含该事件。如果已知事件不在结果中，继续检查原因，不能仅因分页结束或补投完成就说日志齐全。核实前说明缺少哪些事件，不称为全量。
