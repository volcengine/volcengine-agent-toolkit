## 路径选择

用户接受部分结果，或全量受实际阻碍且部分结果仍有用时，可交付已校验文件并突出已覆盖与未完成范围；不得把部分结果称为全量。

导出授权不包含停止投递或删除资源，这些动作需单独明确授权。

已有查询／导出背景下，用户反馈仅导出当前页或 200 条时，按补全匹配结果处理；明确要求定位控制台缺陷或仅要步骤时不自动下载。

1. 用户只要当前集合时保存该集合。用户要全部时，判断条件和规模，而非仅根据“全部”二字选工具。
2. 近 90 天且条件受基础接口支持、结果已知不超过 200 条时，按 event-query.md 直接基础导出并检查 Complete／HasMore；不必先查已投递的日志。
3. 规模未知且基础条件可满足时，可有限查询或尝试基础导出；结果完整则交付。发现上限或 HasMore=true 后，将局部状态留为内部证据，继续查找并下载已投递的日志，不能据此称全量。
4. 已知超限、条件不受支持、超出基础窗口或已有符合需求的 TLS／TOS 日志时，直接检查已投递的日志。不要仅为估算分页数增加统计；完整性核验需要时可统计。
5. 已投递的日志可用则下载；所需的已投递日志确实缺失且符合补投范围时，按 backfill-delivery-tasks.md 准备具体方案并确认。超出恢复能力时报告范围缺口。

## 查找已投递的日志

按信息可得性推进，不要求用户逐项指认资源：

1. 优先复用本次指定或上下文中已有的跟踪、TLS Topic、TOS 路径，但先核实账号、权限、实际审计字段与覆盖。不要仅凭资源名称判断是否可用。
2. 查询本次操作的账号可见跟踪，纳入相关组织范围；从有效配置读取 TLS／TOS 存储桶。当前配置和开启时间仅为线索，不证明历史持续投递。
3. 没有当前跟踪或覆盖不匹配时，检查历史补投任务、已知下载任务及已有交付记录中指向的资源；旧任务可提供保存位置，但旧时段任务不是新时段覆盖证据。
4. 对已知地域、项目或桶在权限允许的范围内查找日志，读取主题保留策略、日志样本或限定前缀的对象清单；不遍历所有账号和地域。确有必要扩展范围时解释目的。
5. 已核实 Topic／桶可直接下载时，不因原跟踪被删除而重建。多个主题或存储桶中的日志能补齐所需范围时，核对各自的时间和事件范围，避免重复；所属账号、访问权限或日志保存位置仍无法确定才一次询问所缺信息。
6. 查找日志时都要核实来源账号和资源账号、地域、保留期、真实事件时间与写入时间、采集范围以及访问权限。仅可访问主题或看到日志账号字段不等于调用身份已经核实。

### 原始下载后本地筛选

索引缺失不等于不能导出。若字段可从原始事件可靠还原，且数据规模、传输与保存影响合理，先考虑下载覆盖原条件的日志集合，再在本地按账号、EventTime、事件源、资源和读写条件精确筛选；不因缺索引就自动新建主题、重建索引或补投。

- 下载范围是原需求的可证明超集，不能为了简化查询漏掉事件源或条件。保留原始事件字段，混存日志不直接当成审计日志。
- 核对实际写入时间与 EventTime；补投数据按真实写入窗口下载，再按事件发生时间筛选。
- 筛选后核对账号、条件、时区和范围边界，必要时按 EventID 去重并记录数量。
- 上游下载完整和本地筛选完整分别验证；部分下载上运行正确筛选也不是全量结果。涉及显著扩大下载范围、额外费用或数据保存影响时，先说明必要影响并按授权范围处理。

### TOS 已投递日志下载

所需日志已投递到 TOS 时加载 `volcengine-tosutil`，分别核对调用身份、资源账号、桶地域与权限，在指定前缀下查找实际的审计日志对象。核对投递路径、对象时间与事件时间、分片清单和分页结束状态，不能只下载首屏对象。下载后验证压缩包与内容可读性，按原账号、EventTime 和筛选条件生成结果，避免混入其他账号或重复日志。无法证明对象清单与历史覆盖时说明边界，不凭“桶存在”宣称完整。


## 默认路径：TLS 离线下载任务

已选择 TLS 路径的全量或大批量日志任务，优先使用 TLS 离线下载任务。日志已在 TLS 中时直接下载；缺少所需的已投递历史日志且符合补投范围时，先按 [backfill-delivery-tasks.md](backfill-delivery-tasks.md) 补投，完成后再下载。重新补投不能解决下载任务超限。

通过 `volcengine-tls` 创建下载任务、查询状态并获取文件；具体命令和参数遵循该技能。

1. 固定本次账号、TLS 日志主题、查询条件和绝对时间范围，沿用已核实的 TLS 身份、地域和服务地址。已有查询的导出不重新计算相对时间；由程序转换接口所需时间单位。
   创建下载任务前，按 [advanced-query.md](advanced-query.md) 核对要查询的日志主题的实际字段与索引，读取少量原始样本，并用拟用于下载的查询做小规模检索，确认查询受支持且筛选语义符合用户要求；同一日志主题和查询条件已有有效验证证据时复用，不重复探查。无匹配样本时，不能仅凭空结果认定查询正确或历史无日志，应结合索引、原始字段及时间覆盖判断。字段不支持直接检索时，按“原始下载后本地筛选”选择能够包含全部匹配记录的日志集合，再验证本地筛选依据，不静默删条件或修改索引。
2. 按 `volcengine-tls` 的当前接口说明构造下载请求并执行其预检。本地请求预检不执行实际查询，不能替代上一步对查询可用性和筛选语义的验证。明确的导出请求可覆盖相同范围的下载任务；不因此自动创建跟踪、补投或修改主题。使用唯一任务名，明确普通日志或分析结果类型、格式、压缩方式和下载条数上限；不能用示例中的小 Limit 截断“全部”。全量任务不允许不完整查询结果；完全精确查询选项按账号实际支持情况设置，不能假定已开通。
3. 创建后保存 TaskId、日志主题和完整请求。结果不明时，通过 `volcengine-tls` 按主题、任务名及任务 ID 核对，必要时分页查找，不重复创建。按任务 ID 合理轮询至终态；生成中继续等待，失败或取消说明原因。当前会话无法继续等待时保留任务信息与状态供恢复，没有调度能力或授权不承诺后台持续执行。
4. 文件生成完成后，通过 `volcengine-tls` 获取下载地址并保存文件；链接过期重新获取地址，不重新创建任务。不将签名下载地址写入持久记录或作为公开链接传播。校验下载成功及文件可读后再交付，创建任务或取得链接不等于下载完成。
5. 按任务状态、截断信息、实际条数和文件结果判断完整性；文件生成中断、部分结果或达到请求 Limit 时不能仅凭有文件就称为全部。需要时缩小时间范围、分多次下载；固定原查询条件，由程序划分覆盖原区间的时间段并按接口边界语义避免重叠和遗漏。同一时间点数据仍超限且无法可靠拆分时，明确限制，不无限重试。
6. 分段任务逐个确认完成并核实文件，汇总时间范围、条数和文件清单；部分分段失败时只重做对应分段，不重复合并旧文件。所有分段覆盖原范围且无截断证据时才报告全部导出完成；这不证明历史投递从未遗漏。

[TLS 下载日志文档](https://docs.volcengine.com/docs/TorchLogService/Downloadlogs?lang=zh)规定：原始日志单任务最多 2000 万条且不超过 20 GiB，分析结果最多 100 万条且不超过 2 GiB；大数据量推荐缩小时间范围、分多次下载。执行时核对当前限制；超限可能仅生成部分文件。下载任务记录及文件保留 1 天，生成后及时下载。下载期间不要修改查询依赖的索引。

## 备用路径：检索分页导出

适用于用户明确选择分页导出，或离线下载不可用的情况。按 `volcengine-tls` 当前接口说明执行，固定账号、主题、绝对时间和查询条件。

- 普通日志逐页核对扫描状态与续页标记，扫描完整且到达末页后再汇总文件。达到上限或部分扫描时保留已取得结果及缺口，继续恢复或切换路径。
- SQL 分析按语句及接口限制解释结果范围，保留用户的 limit/offset。
- 校验实际文件可读、条数和范围匹配。工具只返回文件路径时读取文件；全量结论同时核对扫描完成和分页结束证据。

## 统计与核对

- 用户只要统计结果时，已有 TLS 日志可满足条件和时间范围的，直接统计，无需先下载。用户要求导出后分析的，文件校验完成后继续分析。
- 统计时说明账号、时间范围、筛选条件和计数单位（事件、请求、资源或 IP）。按 EventID 去重时同时核对账号；缺失 ID、内容冲突或无法解析的记录单独说明。IP 统计区分有效地址、缺失和非地址值。
- 比较控制台、API、TLS/TOS 的数量时，先对齐时间、条件、事件类型和去重口径，再检查分页、截断及日志覆盖范围。
- 有已知事件或 RequestID 时，核对导出结果是否包含该事件。分页结束或补投完成不能解释已知事件缺失；核实前说明缺口，不称为全量。
