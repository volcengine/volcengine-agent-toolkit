# 账号与操作规则

接口参数与操作步骤见对应能力参考。

## 账号与范围

- 优先使用用户指定或上下文已确认的账号；否则沿用已核实的当前账号。存在账号歧义时，先确认再执行依赖该账号的操作。
- 优先复用原有已授权身份；认证来源发生变化或无法确认一致时，重新核实实际调用身份。同名 profile、可访问资源或日志中的账号字段均不能单独证明调用身份一致。跨账号操作同时核实日志来源账号、存储资源所属账号及授权关系。
- 身份不一致时暂停相关操作，先检查已有授权及身份选择；确需重新授权时再请求用户登录。登录恢复按对应工具技能处理。
- 工具缺少凭证时，先检查现有授权能否复用，再判断是否需要重新登录或补充权限。
- 切换账号后重新核实本次操作的账号与实际身份，旧结果不得混入新结果。
- 保留用户要求的完整产品范围、时间与条件组合，不因接口限制静默缩小。
- 空结果仅代表已核实范围内未查到，不证明事件未发生。

## 操作授权

- 已授权范围内的只读操作直接执行。
- 新建或修改存储资源、跟踪、补投、索引及模板前，完成必要预检，核对授权是否覆盖具体动作、涉及的资源范围及重要影响。已确认方案直接执行；需补充授权时，一次说明待确认内容。
- 确认提示直接说明动作和实际影响，内部执行依据仅按用户需要或宿主要求披露。具体预检、费用、持续投递与保留策略要求见对应能力参考。
- 授权仅覆盖已明确的动作和范围，不自动扩展到其他操作。组织级、跨账号操作的范围及授权必须明确。
- 写请求结果不明时先查询当前状态，避免重复提交。回读确认后才能说“已生效”，接口受理不代表异步任务完成。

## 用户沟通与证据

- 仅呈现影响当前结论、执行或用户决策的信息；先说结果、实际范围和可用文件，不逐项汇报内部检查。异步等待中的重复状态不逐次转述；按宿主要求提供必要更新。
- API 调用请求 ID、游标、CLI 参数、身份选择和原始响应保留在必要诊断记录，排障或用户需要时再展示；不记录密钥、令牌或签名下载地址。
- 诊断按需要给出事件时间、操作、身份、来源 IP、错误和关联资源；按实际事件语义解释成功或失败，不扩大到业务整体结论。
