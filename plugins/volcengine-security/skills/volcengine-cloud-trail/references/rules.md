# 账号与操作规则

接口参数和具体步骤见各功能的参考文档。

## 确认账号和查询范围

- 使用用户指定或此前已确认的账号；没有指定时，使用已核实的当前账号。不确定要操作哪个账号时，先问清楚。
- 尽量使用已有登录。凭证来源发生变化，或无法确认是否仍为同一身份时，重新查询实际调用身份。两个工具使用同名 profile、能够访问同一个资源，或日志中出现同一账号，都不能证明它们使用了相同身份。跨账号操作还要确认日志来自哪个账号、存储资源属于哪个账号，以及是否有相应权限。
- 实际身份与本次操作的账号不一致时，先暂停操作，检查已有登录和凭证配置。只有确实需要重新登录时，才请用户授权；具体步骤按对应工具技能执行。
- 工具提示缺少凭证时，先检查能否使用已有登录，再判断是否需要登录或补充权限。
- 切换账号后重新核实调用身份，不把旧账号的结果混入新账号的结果。
- 按用户要求保留全部产品、时间范围和筛选条件。接口不支持时说明限制，不自行缩小范围或删掉条件。
- 没查到记录，只能说明本次查询没有匹配结果，不能据此断定事件没有发生。

## 操作授权

- 用户已授权的只读操作直接执行。
- 新建或修改存储资源、跟踪、补投任务、索引或模板前，先检查所需配置和权限，并确认用户同意了哪些操作、涉及哪些资源、会产生什么影响。方案已经明确确认过，就直接执行；还缺少授权时，一次说清需要确认的内容。
- 请用户确认时，直接说明要做什么、会产生什么影响。内部执行依据只在用户需要或当前运行环境要求时说明。费用、持续投递和保留时间等要求见对应功能的参考文档。
- 不把用户对某项操作的同意扩展到其他操作。组织级和跨账号操作也要明确涉及的账号、资源和授权。
- 写操作返回结果不明确时，先查询当前状态，不直接重复提交。重新查询并确认修改生效后，才能说“已生效”；接口返回成功不代表异步任务已经完成。

## 用户沟通与证据

- 先说结果、实际查询或操作的范围，以及可用文件。只补充影响结论、后续操作或用户决定的信息，不逐项汇报内部检查。等待任务完成时，不重复汇报相同状态，同时遵守当前运行环境的进度更新要求。
- 请求 ID、分页游标、CLI 参数、所用身份和原始响应按需保留用于排查，用户需要时再展示。不记录密钥、令牌或带签名的下载地址。
- 排查问题时，按需提供事件时间、操作、调用身份、来源 IP、错误和相关资源。根据事件本身解释成功或失败，不把一次接口调用的结果当成整个业务的结果。
